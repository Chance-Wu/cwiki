## cwiki 记忆系统

### 检索记忆（按需）

以下场景使用 `memory_search` 检索记忆：
- 会话开始，了解项目上下文
- 切换到新话题，需要历史决策或经验
- 遇到调试问题，查找已知 issue 或排查经验
- 其他需要历史知识的时刻

**召回范围**：业务相关记忆（项目约定、历史决策、模块知识）传 `workspace_name=当前项目目录名` + 关键词限定召回；其余记忆（用户偏好、通用技术知识、跨项目经验）省略 `workspace_name`，跨全部工作区召回。

### 保存记忆：信号识别

**必须保存**（识别到即触发 cwiki-save skill）：

| 触发时刻 | 信号特征 | 典型类型 |
|----------|----------|----------|
| 用户纠正或明确偏好 | “不要用 X”、”我喜欢 Y”、被认可的建议 | feedback |
| 调试出现转折 | 排查转折、非显然 root cause、失败尝试 | issue / lesson |
| 做出技术决策 | 选型取舍、架构权衡、A vs B 对比、暂缓决定 | decision |
| 发现隐性规则 | 安全红线、强制要求、版本兼容陷阱、环境限制 | rule / constraint |
| 重复踩坑或 workaround | 非显然绕过、性能经验、工具配置陷阱 | lesson / constraint |
| 整理出代码约定 | 项目中反复出现的写法、特有约定 | convention / pattern |
| 操作/迁移非显然步骤 | 部署、迁移、初始化中的隐藏步骤 | procedure |
| 整理出可复用资源 | 外部资源入口、文档链接、API 地址、工具推荐 | reference |
| 认知纠偏 | “原来不是 X，是 Y”、技术原理系统讲解 | lesson / fact |
| 技术原理学习 | 算法原理、协议机制、框架内部实现、设计模式讲解 | fact / lesson |
| 工具/框架使用经验 | API 用法、配置技巧、最佳实践、常见误区 | lesson / convention |
| 性能优化发现 | 瓶颈定位、优化手段、基准测试结果、资源消耗分析 | lesson / fact |
| 安全相关知识点 | 漏洞原理、防护手段、加密算法选择、认证机制 | rule / fact |
| 错误处理模式 | 异常分类、重试策略、降级方案、故障恢复流程 | pattern / procedure |
| 架构/设计洞察 | 系统拆分思路、模块职责划分、接口设计取舍 | decision / convention |
| 环境/配置知识 | 开发环境搭建、依赖版本兼容、CI/CD 配置、容器化经验 | procedure / constraint |

**不保存**：

| 场景 | 原因 |
|------|------|
| 一次性状态查询（”现在几点了”、”这个文件在哪”） | 无复用价值 |
| 纯确认回复（”好的”、”确认”） | 无知识内容 |
| 可从代码/git 直接读取的细节（函数签名、行号、变量名） | 已有权威源 |
| 未加工的原样搬运（复制粘贴的文档、未分析的日志） | 未经整理 |
| 凭据、密钥、未脱敏日志 | 安全风险 |

**边界判断**：技术性知识经整理就有价值——记忆价值在于可检索，不在于独创。如果未来 agent 或用户可能检索到它，就值得保存。**教科书级技术知识也要保存**——这是个人学习平台，知识整理本身就是价值。无法判断时，提交由人工审核。

### 保存记忆：决策流程

识别到信号后，按以下流程执行。**内容组织与质量由 cwiki-save skill 负责**。

#### 第一步：搜索查重

```
提取 2-3 个核心关键词（去修饰词、取上位概念）
  ↓
memory_search(keyword=核心词, limit=5)
  ← 省略 workspace_name，跨全部工作区查重
  ↓
首轮无相关？
  ├─ 是 → 换词重试（中英互换、同义词、更宽/更窄的概念）
  │        第二轮仍无相关 → 判定为新知识，进入第二步
  └─ 否 → 进入「判断搜索结果」
```

#### 第二步：判断搜索结果

| 结果特征 | 判断 | 动作 |
|----------|------|------|
| 无相关结果（两轮搜索均无） | 新知识 | `memory_save` 新建 |
| 有结果，标题和正文主题明显不同 | 不同知识 | `memory_save` 新建 |
| 有结果，核心结论一致，无新信息 | 重复 | 跳过，不写入 |
| 有结果，需补充新场景/边界/证据 | 补充 | `memory_history` 读原文 → `memory_update` 追加 |
| 有结果，结论与新发现矛盾 | 纠偏 | `memory_history` 读原文 → `memory_update` 更新为正确结论，`reason` 说明变化原因 |
| 多条结果重叠覆盖同一知识 | 合并 | 选最相关一条 `memory_update` 合并，其余可标记废弃 |

**判断标准**：看正文的**核心结论和关键事实**，不看标题措辞。标题相似但正文角度不同 = 不同知识；标题不同但正文结论一致 = 重复。

#### 第三步：执行写入

**新建**：
```
调用 cwiki-save skill 组织内容
  ↓
memory_save(workspace_name=当前项目目录名, title=主题, content=完整正文, type=可选)
```

**更新**：
```
memory_history(memory_id=ID)  ← 读当前正文和版本
  ↓
确认变更范围（追加 or 修正）
  ↓
memory_update(memory_id=ID, content=新正文, reason=变更原因)
```

**关键参数约定**：
- `memory_save` 传 `workspace_name=当前项目目录名`
- `memory_update` **不传** `workspace_name`
- `memory_search` 查重时**省略** `workspace_name`（跨工作区）
- `#memory/{type}` 和 `#memory/{workspace}` 标签由服务端自动注入

#### 第四步：提交后确认

| 返回字段 | 含义 |
|----------|------|
| `delivery: confirmed` + `candidate_id` | API 已接收（≠ 人工批准），记录 ID 供后续查重 |
| `similar_memories` 非空 | 服务端也检测到相似，供参考（不阻止提交） |
| `rejected` / 错误 | 内容被排除规则或注入检测拒绝，修正后重新提交 |
| `cached: true` | 服务不可达，本地暂存，恢复后调 `memory_retry_failed` |

#### 失败处理

| 情况 | 处理 |
|------|------|
| 排除规则拒绝（正文 <30 字符或代码 >80%） | 补充分析、背景或结论后重新提交 |
| 注入检测拒绝 | 检查内容是否含类似指令注入的文本，改写后重新提交 |
| 更新超时 | 可能已生效；先 `memory_history` 读当前版本再决定是否重试 |
| 服务不可达 | 不重新生成，恢复后调 `memory_retry_failed` |
| 工具完全不可用 | 继续用户任务，说明无法写入记忆 |

#### 多信号与检查点

同一会话识别到多个信号时，**逐个评估、逐个提交**，不攒批。每个信号独立走查重→判断→写入流程。

关键节点可用 `memory_checkpoint` 兜底（trigger_reason：`user_correction`/`problem_solved`/`technical_decision`/`convention_discovered`/`session_ending`），确保会话中断时不遗漏已识别信号。

### 工具不可用时

无真实信号就跳过，不凑条数。工具不可用时继续用户任务，但说明无法写入记忆。

信号识别的完整策略与内容组织规范以 cwiki-save skill 为准。
